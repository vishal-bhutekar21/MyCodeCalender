# Production Reliability Audit

## 1. Contest Reminder & Alarm Subsystem

The contest reminder subsystem is implemented in [ReminderScheduler.kt](file:///d:/Projects2026/dsaapp/core/notifications/src/main/java/com/mycodecalendar/core/notifications/ReminderScheduler.kt) and [NotificationHelper.kt](file:///d:/Projects2026/dsaapp/core/notifications/src/main/java/com/mycodecalendar/core/notifications/NotificationHelper.kt).

### 1.1 Silent Erasure of Alarms on Device Reboot (Critical Flaw)
* **Underlying Android OS Behavior**: When an Android device is powered off or rebooted, the Android OS `AlarmManager` clears **all** registered alarm timers and pending intents from memory.
* **Flaw in CodeCalendar**:
  1. There is no `android.permission.RECEIVE_BOOT_COMPLETED` declared in [AndroidManifest.xml](file:///d:/Projects2026/dsaapp/app/src/main/AndroidManifest.xml).
  2. There is no `BroadcastReceiver` listening for `android.intent.action.BOOT_COMPLETED`.
  3. Although reminders are saved to the Room database table `reminders`, the application **never queries Room upon boot** to reschedule them.
* **Impact**: Whenever a user restarts their smartphone, **100% of their scheduled contest reminder alarms are silently lost**. Users will not receive notifications 15 minutes before contests start.

---

### 1.2 Integer Collision in Notification IDs
In [ReminderScheduler.kt:L40](file:///d:/Projects2026/dsaapp/core/notifications/src/main/java/com/mycodecalendar/core/notifications/ReminderScheduler.kt#L40):
```kotlin
val notificationId = contest.id.hashCode()
```
* **Flaw**: Using string `.hashCode()` to generate notification IDs carries a mathematical risk of hash collisions.
* **Impact**: If two distinct contests from different platforms hash to the same 32-bit integer, setting a reminder for the second contest cancels or overwrites the reminder for the first contest in the Android notification manager.
* **Remediation**: Use an auto-incrementing integer primary key generated by the Room `reminders` table.

## 2. Calendar Contract Subsystem (`CalendarContractManager`)

In [CalendarContractManager.kt](file:///d:/Projects2026/dsaapp/core/calendar/src/main/java/com/mycodecalendar/core/calendar/CalendarContractManager.kt#L13-L55):
```kotlin
val uri: Uri? = cr.insert(CalendarContract.Events.CONTENT_URI, values)
```

### 2.1 Missing Manifest Permissions (`SecurityException`)
* **Android OS Requirement**: Accessing `CalendarContract.Events` and `CalendarContract.Reminders` on Android 6.0+ (API 23+) strictly requires runtime permissions:
  * `android.permission.READ_CALENDAR`
  * `android.permission.WRITE_CALENDAR`
* **Inspection of Manifest**: [AndroidManifest.xml](file:///d:/Projects2026/dsaapp/app/src/main/AndroidManifest.xml) declares only `INTERNET`, `POST_NOTIFICATIONS`, and `SCHEDULE_EXACT_ALARM`.
* **Impact**:
  1. When a user taps "Export to Google Calendar" in `ContestDetailScreen`, Android throws a fatal `java.lang.SecurityException: Permission Denial: reading/writing com.android.providers.calendar.CalendarProvider requires android.permission.READ_CALENDAR / WRITE_CALENDAR`.
  2. Because `CalendarContractManager.addContestToCalendar` wraps the insert in `runCatching` / `try-catch`, the crash is caught, but the function **always returns a failure result**.
  3. The calendar export feature is **100% non-functional in production builds**.

## 3. Background Synchronization (`SyncManager` & `ContestSyncWorker`)

In [SyncManager.kt](file:///d:/Projects2026/dsaapp/sync/src/main/java/com/mycodecalendar/sync/SyncManager.kt):
```kotlin
class ContestSyncWorker(appContext: Context, workerParams: WorkerParameters) : CoroutineWorker(appContext, workerParams) {
    override suspend fun doWork(): Result {
        return try {
            println("Background ContestSyncWorker executing successfully.")
            Result.success()
        } catch (e: Exception) {
            Result.retry()
        }
    }
}
```

### Flaws Identified
1. **Placeholder Implementation**: `ContestSyncWorker` contains only a `println()` statement. It does not call `FakeRepository.refreshContests()`, does not update Room DB, and does not synchronize alarms.
2. **Never Scheduled**: Searching the entire repository confirms that `SyncManager(context).schedulePeriodicSync()` is **never called anywhere in the app lifecycle** (neither in `MainActivity.onCreate` nor in any custom `Application` class).
3. **Impact**: The app possesses **zero background synchronization**. Contest data is updated only when the user explicitly opens the app in foreground.

## 4. Authentication Persistence & Account Loss

In [AuthScreen.kt:L146](file:///d:/Projects2026/dsaapp/feature/onboarding/src/main/java/com/mycodecalendar/feature/onboarding/AuthScreen.kt#L146):
```kotlin
// Google Sign-In button handler
auth.signInAnonymously().addOnCompleteListener { authTask ->
    val user = auth.currentUser
    user?.updateProfile(...)
    ...
    onAuthSuccess(displayName, "Google", userEmail, userPhoto)
}
```

### Flaws Identified
* When the user authenticates with Google via the account chooser, the app ignores the Google OAuth ID token and executes `auth.signInAnonymously()`.
* **Impact**:
  1. A temporary, anonymous Firebase UID is generated.
  2. If the user clears app storage, uninstalls the app, or installs the app on a second device, **their account and linked platforms cannot be recovered**.
  3. Logging in with the same Google email on another device generates a different anonymous UID, resulting in split identities and lost streaks.

## 5. Cloud Push Notification Inoperability

In [NotificationHelper.kt:L22](file:///d:/Projects2026/dsaapp/core/notifications/src/main/java/com/mycodecalendar/core/notifications/NotificationHelper.kt#L22):
```kotlin
const val CHANNEL_FCM_BROADCASTS = "fcm_broadcasts_channel" // Cloud push / Cloudflare worker
```

### Flaws Identified
1. The project does not include the `com.google.firebase:firebase-messaging` dependency in [libs.versions.toml](file:///d:/Projects2026/dsaapp/gradle/libs.versions.toml) or [app/build.gradle.kts](file:///d:/Projects2026/dsaapp/app/build.gradle.kts).
2. No class extending `FirebaseMessagingService` exists in the repository.
3. No `<service>` tag for FCM is registered in [AndroidManifest.xml](file:///d:/Projects2026/dsaapp/app/src/main/AndroidManifest.xml).
4. **Impact**: The app cannot receive remote push notifications from either Firebase Cloud Messaging (FCM) or Cloudflare Workers.
